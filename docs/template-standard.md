# 模板使用与管理规范

## 分类与命名

一级目录按文件类型划分：`spreadsheets`、`documents`、`presentations`。需要新格式时，在实际样例到位后新增目录并同步扩展检查脚本的分类列表。业务用途（如采购、项目、财务）使用 `tags` 表达，避免同一模板在多个目录重复存放。

每个模板使用稳定 ID，例如 `micas-excel-template`；目录名使用小写英文和连字符，例如 `excel-template`。正式文件位置为：

```text
templates/<分类>/<用途>/v<主版本.次版本.修订号>/<原始文件名>
```

原附件保留文件名、扩展名和全部字节；不为“清理格式”而重新保存。不明用途先使用中性名称并标记待确认。不要虚构适用场景或填写规则。

## 使用规则

- 从指定版本复制后填写；正式模板不存放业务交付成果。
- 使用前阅读对应 README，确认所需软件与已知限制。
- 保留公式、样式、品牌元素和归属信息；需要改变结构时先建立新版本。
- 外部字体、链接、宏、插件或其他依赖若存在，必须在说明中列出；不能仅凭文件格式推断其不存在。
- 公开仓库只接收适合公开的模板，提交前检查真实客户、员工、账户和其他敏感数据。

## 版本与状态

使用三段版本号：`1.0.0`。结构或使用方式不兼容时升级主版本；兼容的功能扩展升级次版本；修正升级修订号。任何模板文件字节变化都新增版本目录，不能原地替换已收录版本。纯文档说明修正可直接修改说明，记录于 CHANGELOG。

状态只允许 `draft`（待确认）、`active`（正式收录）、`deprecated`（不推荐新使用，历史保留）。弃用时保留原文件，说明原因及替代版本。不要把业务验收与收录状态混为一谈。

## 登记清单

`templates/catalog.json` 是唯一机器可读索引，`schema_version` 初始为 `1`。每个版本一个条目，必填字段：

| 字段 | 含义 |
| --- | --- |
| `id`, `name` | 稳定模板 ID、显示名称 |
| `category`, `tags` | 文件分类、业务或管理标签 |
| `version`, `status` | 版本、收录状态 |
| `path`, `readme` | 仓库根目录相对路径、使用说明路径 |
| `original_filename` | 原始附件文件名 |
| `source`, `added_on` | 来源说明、收录日期 |
| `size_bytes`, `sha256` | 字节大小、原文件 SHA-256 |

更改索引格式时同步更新 `schema_version`、检查脚本和本文档。脚本检查登记一致性与文件完整性；它不能证明版权、视觉效果、业务逻辑或公式结果正确，也不能替代版本不可覆盖的人工审查。

## 后续扩展

每收到一个新样例，新增对应用途目录、说明和登记条目。衍生模板独立登记并在说明中写明来源模板及版本；生成器、预览图和自动化代码待实际需要时加入，不替代原始附件。若未来接入搜索或下载页面，直接读取登记清单，避免建立另一份模板数据源。
